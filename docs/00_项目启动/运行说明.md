# 运行说明

项目有两份运行方式。**开发在 WSL，查看/运行可以在 Windows。**

## 一、在 WSL 里运行（开发用）

```bash
cd /home/wannnlee/researchpilot
conda run -n rp python -m streamlit run app.py
```

环境已经建好（`rp`，Python 3.11.17 / Streamlit 1.65.0 / PyMuPDF 1.28.2）。
若换了机器：

```bash
conda create -n rp -y python=3.11
conda run -n rp pip install -r requirements.txt
```

Windows 的浏览器直接打开 http://localhost:8501 就能看到界面，WSL2 会自动转发端口。

## 二、在 Windows 里运行（E 盘镜像）

目标目录：`E:\给wsl的文件\ResearchPilot`

**双击 `run_windows.bat`。** 它会自动做四件事：检查 conda、创建或复用名为 `rp`
的环境（Python 3.11）、按需安装依赖、启动 Streamlit。

或者手动在 Anaconda Prompt 里执行：

```bat
cd /d E:\给wsl的文件\ResearchPilot
conda create -n rp -y python=3.11
conda activate rp
pip install -r requirements.txt
streamlit run app.py
```

然后浏览器打开 http://localhost:8501 。

### Windows 侧的三个注意点

1. **运行数据和你的 WSL 是分开的。** 界面在 Windows 跑时，数据库与上传文件写在
   `E:\给wsl的文件\ResearchPilot\outputs\` 下，与 WSL 里的 `outputs\` 不是同一份。
   两边各记各的，不会互相覆盖。
2. **`.env` 两边各放一份。** 同步脚本会排除 `.env`，所以你在 E 盘填的 API Key
   不会被覆盖，也不会被带回 WSL。
3. **原始地震数据在 Windows 上只能通过 `\\wsl.localhost\...` 访问**。
   文献功能不受影响。

## 三、自检（不需要界面）

```bash
conda run -n rp python scripts/smoke_m1.py
```

通过时会打印四项 PASS。

## 四、为什么可以直接启动，不用回答首次运行的问题

项目根目录有一份 `.streamlit/config.toml`，`streamlit run app.py` 会自动读取它
（会覆盖 `~/.streamlit/config.toml`）。里面三项：

| 配置 | 值 | 作用 |
|---|---|---|
| `server.showEmailPrompt` | `false` | 关掉 Streamlit 首次运行的邮箱询问 |
| `server.headless` | `true` | 不自动拉起浏览器（WSL 里没有可用浏览器） |
| `browser.gatherUsageStats` | `false` | 关掉遥测与相应提示 |

前两项是必需的：Streamlit 1.65 首次运行会在终端里问一次邮箱，而 `conda run`
和双击 bat 都没有可交互的标准输入，回车送不进去，进程会直接以
`conda run streamlit run app.py failed` 结束。关掉这个询问后，两种启动方式都能一次跑通。

Windows 侧不受影响：`run_windows.bat` 用 `--server.headless false` 把自动开浏览器
覆盖回来，邮箱询问仍由 `showEmailPrompt=false` 关着。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| `conda` 不是内部或外部命令 | 用「Anaconda Prompt」打开，或把 `D:\miniconda\Scripts` 加进 PATH |
| 双击 bat 一闪而过 | 手动在 Anaconda Prompt 里跑 `run_windows.bat`，看完整报错 |
| 界面提示「未配置大模型」 | 正常降级，不影响上传与解析。要启用 AI 功能就填 `.env` |
| 端口 8501 被占用 | 加 `--server.port 8502` |
| 终端出现 `Welcome to Streamlit! ... Email:` 后启动失败 | 首次运行的邮箱询问被触发。确认 `.streamlit/config.toml` 还在项目根目录；临时绕过可加 `--server.headless true` |

## 六、开发闭环：WSL 改完必须同步到 E 盘

**验证在 E 盘做，开发在 WSL 做。** 所以每次在 WSL 改完文件，必须立刻同步一次，
否则你在 `E:\给wsl的文件\ResearchPilot` 里跑到的还是旧代码：

```bash
cd /home/wannnlee/researchpilot
bash scripts/sync_to_windows.sh
```

同步是 `rsync -a --delete`，但下面这些**不会**被删除或覆盖，可以放心：

| 排除项 | 原因 |
|---|---|
| `outputs/`、`logs/` | Windows 侧自己运行产生的数据，与 WSL 各记各的 |
| `.env` | 两边的 API Key 各放一份 |
| `.vscode/` | 你在镜像里打开的编辑器配置 |
| `.git/`、`.refs/`、`.agents/`、`.codex/`、缓存目录 | 开发侧产物，不属于运行所需文件 |

### E 盘上的数据库会自动升级

关系层（v1.3）新增了 `workflow_nodes`、`method_relations`、`schema_meta` 三张表。
Streamlit 启动时会执行建表语句，所以 **E 盘那边的库在你下次启动应用时自动补齐**，
不需要手工迁移。想单独确认或手工执行：

```bat
conda activate rp
cd /d E:\给wsl的文件\ResearchPilot
python scripts/db_status.py      REM 只读查看表与行数
python scripts/migrate_db.py     REM 补齐缺表（幂等）
python scripts/smoke_relations.py  REM 关系层验收测试（在临时库上跑）
```

## 七、依赖装进哪个环境

**界面跑在哪，包就必须装在哪。** 装到别的 Python 里，界面照样报缺失。

### 怎么一眼看出界面用的是哪个环境

左侧栏最下面的「运行环境」面板会直接列出：Python 解释器全路径、PyMuPDF 版本、
模型配置、数据库路径、schema 版本。PDF 那行如果显示「**未安装**（上传会失败）」，
说明当前环境缺 PyMuPDF。

也可以在代码里查：

```bat
python -c "import sys, pymupdf; print(sys.executable, pymupdf.__version__)"
```

### 当前两边的实际环境

| 平台 | 解释器 | 已有 |
|---|---|---|
| WSL | `~/miniconda3/envs/rp/bin/python` | streamlit 1.65.0 / pymupdf 1.28.2 |
| Windows | `D:\miniconda\envs\noisepy\python.exe` | streamlit 1.65.0 / pymupdf 1.28.2 |

Windows 上界面实际跑在 `noisepy` 环境里（`D:\miniconda\envs\` 下没有 `rp` 环境）。
2026-10-08 曾因此报 PyMuPDF 缺失——那个环境有 streamlit 但没有 pymupdf。
如果以后改用 `run_windows.bat` 创建独立 `rp` 环境，记得那个环境也要装一遍：

```bat
conda activate rp
python -m pip install -r requirements.txt
```

### 四个自检脚本（都不需要浏览器）

```bat
python scripts/db_status.py        REM 只读：表、行数、项目与文献清单
python scripts/smoke_ui.py         REM 界面能否启动、建项目、开四个工作台
python scripts/smoke_relations.py  REM 关系层 13 项验收
python scripts/smoke_m1.py         REM M1 链路（配置/数据库/PDF 解析/LLM 降级）
```

前三个默认写临时数据库，不会碰 `outputs/researchpilot.db`。

### 文献核查相关（C1）

```bat
conda run -n rp python tests/test_bibliography_offline.py   REM 17 项离线回归，不联网
conda run -n rp python scripts/check_external_apis.py       REM 在线联通性：Crossref + OpenAlex
conda run -n rp python scripts/c1_e2e_check.py --no-cache   REM 端到端：真实 PDF + 真实 API
conda run -n rp python scripts/verify_meta.py --paper paper_xxxx   REM 核查某一篇
```

### 文献关系相关（C2）

```bat
conda run -n rp python tests/test_c2_relations_offline.py   REM 12 项离线回归，不联网
conda run -n rp python scripts/fetch_citations.py --paper paper_xxxx --related
conda run -n rp python scripts/c2_e2e_check.py --no-cache   REM 端到端：真实引用网络 + 人工裁决 + 项目隔离
```

`--related` 会把 OpenAlex 的相关文献导入成候选，但**不建立引用边**——
相关性不是引用事实。拉取上限用 `--limit`（默认 20/方向）。

外部请求的超时、重试、限速、缓存都在 `literature/net.py` 里统一处理，
参数见 `.env.example`（`HTTP_TIMEOUT` / `HTTP_MAX_RETRIES` /
`HTTP_MIN_INTERVAL` / `HTTP_CACHE_TTL_DAYS`）。

原始响应缓存到 `outputs/cache/{crossref,openalex}/`，可以逐字复核。
**缓存里是外部服务的原始数据，属于留档证据，不要手工改。**

在 `.env` 里填 `CROSSREF_MAILTO` / `OPENALEX_MAILTO` 会进入对方的礼貌池，
限流更宽；不填也能用。

## 八、端口与数据库对应关系（2026-10-11 起固定）

真实故障：Windows 浏览器打开 `localhost:8501` 时，连到的是 **WSL 开发实例**
（WSL2 会把 localhost 转发进 WSL 虚拟机），而 WSL 那个库只有冒烟测试项目——
看起来就像"我的项目丢了"。所以三个实例的端口与库从此固定：

| 实例 | 端口 | 绑定地址 | 数据库 |
|---|---|---|---|
| WSL 开发实例 | 8501 | 默认 | `/home/wannnlee/researchpilot/outputs/researchpilot.db` |
| WSL 验收实例 | 8502 | 默认 | `/tmp/rp_acceptance/researchpilot.db`（带"测试环境"标识） |
| **Windows 正式使用** | **8601** | **127.0.0.1** | `E:\给wsl的文件\ResearchPilot\outputs\researchpilot.db` |

`run_windows.bat` 的行为：

1. 把端口固定为 8601、绑定 127.0.0.1（只有本机能访问）；
2. 用 `Get-NetTCPConnection` 检查 8601；**被占用就明确提示并停止**，
   绝不自动换端口——静默换端口会重新制造"不知道浏览器连的是哪个库"的混乱；
3. 启动前跑 `scripts/preflight_windows.py`，打印正式库的**绝对路径与记录数**
   （项目 / 文献 / 引用关系 / AI 结论），库不存在时明确警告会新建空库；
4. 启动后打印访问地址 `http://127.0.0.1:8601/`。

注意：端口占用检测**不要用 `netstat | findstr`**。实测在部分调用方式下它会漏判
（端口明明被占用却报空闲），必须用 PowerShell 的 `Get-NetTCPConnection`。
