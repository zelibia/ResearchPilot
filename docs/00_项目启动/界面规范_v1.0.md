# ResearchPilot AI 界面与数据规范 v1.0

生效日期：2026-10-10 ｜ 适用：全部面向用户的界面（四个工作台、侧栏、导出物）

本规范是**长期开发规则**，不是某一轮的任务说明。新增页面、后续 M2 / C3 / M3
的界面从第一行代码起就要满足；`scripts/smoke_ui.py` 里有对应的回归测试守着。

---

## 1. 用户界面不得出现开发内容

面向普通用户的界面上禁止出现：

- 开发任务编号（`M1`、`M2`、`M3`、`C1`、`C2`、`C3`、`UI-01`、`T07` 等）。
- "本页尚未实现""这里将展示某功能"这类大段占位说明。
- 自动化测试结果、测试项目、测试脚本、开发进度。
- 数据库 schema、内部表名、调试用 JSON。
- 与用户科研任务无关的环境配置与技术解释。
- 为测试界面而编造的文献、实验结果、评价指标、研究结论。

这些内容属于开发文档或**受控诊断模式**，不属于用户界面。

## 2. 空状态统一

没有数据时给一句简洁空状态，不解释为什么没实现、不用大段文字填充：

| 场景 | 文案 |
|---|---|
| 未创建方案 | 暂无复现方案 |
| 未执行实验 | 暂无实验记录 |
| 未生成报告 | 暂无科研成果 |

尚未实现的功能**不提供无效按钮**，也不展示虚构示例冒充真实数据。

## 3. 科研信息必须保留

不得为了"页面简洁"删掉真实科研内容。以下内容必须留在数据库，并通过详情面板或
高级信息入口可查：

论文来源与 DOI、元数据冲突、方法关系的证据位置与裁决记录、实验参数、
真实错误日志、结果产物。

严重错误与需要用户处理的冲突必须继续**明显提示**，不能被折叠藏起来。

## 4. 测试与正式数据严格隔离

- 自动化测试一律使用独立临时数据库（各测试脚本自己设 `RESEARCHPILOT_DB`）。
- 测试代码不得向正式用户项目写入模拟数据。
- 现有 `【冒烟测试】` 项目暂不删除；后续演示使用独立的干净数据库。
- 只用于测试的界面、示例文本、内部诊断内容不得进入正式演示。
- 测试数据与真实科研数据必须能一眼区分（冒烟项目标题带 `【冒烟测试】` 前缀）。

例外记录：`scripts/smoke_m1.py` 历史上会写主库，属于已知例外，
跑全量回归时改用 `scripts/smoke_relations.py`（其中 RB-10 在隔离库里覆盖同样的 4 项）。

## 5. 验收约束

后续每个工作台都要同时满足：

| 编号 | 约束 |
|---|---|
| A | 有真实数据时正确显示真实内容 |
| B | 没有数据时显示简洁空状态，不出现开发任务说明 |
| C | 自动化测试不污染正式数据库 |
| D | 界面不把未实现功能伪装成已完成 |
| E | 开发者仍可从日志与受控诊断模式检查问题 |

A–D 由 `scripts/smoke_ui.py` 自动检查；E 由诊断模式保证。

## 6. 受控诊断模式

开发信息不是删除，而是收进一个显式开启的通道。**诊断面板会暴露数据库路径、
原始数据目录、解释器路径等内部信息，因此只认服务端授权，不能只凭公开 URL 打开。**

```bash
# 方式一：服务端环境变量（整个进程生效，部署时由运维决定）
RESEARCHPILOT_DEV_MODE=1 streamlit run app.py

# 方式二：服务端先配令牌，再按会话临时开启
RESEARCHPILOT_DEV_TOKEN=<令牌> streamlit run app.py
#   → http://localhost:8501/?dev=<令牌>      只影响这一个会话
```

规则：

- 未配置令牌时，`?dev=1` 或任何猜测的令牌**一律无效**。
- 令牌用常量时间比较；不匹配时记一条 warning 日志留痕（便于发现公开地址上的越权尝试）。
- 开启后侧栏出现"开发者诊断"面板，包含模型状态、Python 解释器路径、数据库路径、
  schema 版本、原始数据目录等。默认关闭，普通访客看不到。

这四条由 `scripts/smoke_ui.py` 的"安全：开发者诊断只能由服务端授权开启"守着。

## 7. 维护约定

1. 新增界面文案前先问：这是给用户看的，还是给开发者看的？后者一律进诊断模式。
2. 空状态**只写状态**，不写原因和计划。
3. 删除任何界面元素前先确认它不是科研证据（见第 3 节）。
4. `scripts/smoke_ui.py` 的禁用词扫描与空状态断言必须跟着新页面一起扩展。
