# ResearchPilot AI v1.2 — 产品需求文档（独立应用版）

> 版本：v1.2 / 2026-10-08
> 场景：成理 2026 华为智创杯「AI+科研创新」赛道
> 产品名称：ResearchPilot AI —— 面向地震环境噪声研究的文献学习与智能复现平台
> 文件性质：**开发需求基线，不是已完成功能声明**
> 平台选型：**独立 Python + Streamlit 应用。女娲（Nuwax）不再是项目的任何形式的依赖。**

## 变更说明

v1.1 曾把女娲云端定为主入口。经核查后放弃，历史制作材料不再保留。
本版回到独立应用路线，并吸收 v1.1 期间确认的三条结论：

1. 比赛作品本体可以是「可访问链接 / Skill·Agent 文件包 / 可运行代码包」三者之一，**是可选关系**，因此独立代码包完全合规。
2. 技能规范采用 agentskills.io 开放标准（YAML frontmatter + Markdown 指令），可作为方法规范随代码包交付。
3. 平台沙箱类环境不能作为科研证据来源。本项目坚持自持计算与自持记录。

## 1. 项目定位

### 1.1 一句话描述

用户上传一篇或多篇论文，系统帮助梳理研究脉络与方法演进，规划学习与复现路径；用户可选择原文复现、
参考后续文献做方法对比或提出自己的研究设想；执行过程中保存目标、步骤、参数、错误与假设；
最终把**实际结果与起始目标逐条对照**，导出有证据来源的复现报告。

### 1.2 学科边界

- **通用部分**：论文解析、文献检索、学习建议、翻译、方案规划、研究日志、证据与成果组织。
  架构上可扩展到其他科研领域。
- **首个可运行的专业案例**：**地震环境噪声数据处理与互相关/叠加研究**。
- **演示起点**：Bensen et al. (2007)，配合用户提供的后续文献做方法对照。
  不把 Bensen 2007 写成唯一方案，也不声称支持全部后续算法。
- **计算后端**：已通过验证的自研 ObsPy/SciPy 五段式流程为第一后端；NoisePy 为第二后端，
  单独环境验证通过后才接入。**NoisePy 未安装不构成上线阻塞。**

### 1.3 目标用户与痛点

目标用户：正在阅读和复现地震环境噪声相关论文的本科生、研究生及科研新人。

1. 读单篇论文容易脱离前后脉络，把年代较久的方案当成唯一方案。
2. 看懂理论不等于知道怎么选工具、数据、参数与成功判据。
3. 复现过程跨论文、代码、数据、日志、截图，参数与出处容易丢失。
4. 自己的改进想法、失败记录与最终结果很难形成可追溯材料。
5. 写汇报或论文初稿时，容易把未验证的推论写成事实。

### 1.4 产品差异化

**目标—方法—实验—证据—成果的贯通。** 单独的论文问答、NoisePy 命令行、生成 PPT 都已存在；
本作品解决的是这些步骤之间的关联、实验决策与研究过程保真。

## 2. 范围与优先级

### 2.1 P0 —— 必须实现

1. 创建/打开科研项目，上传 1–3 篇 PDF，**关闭应用后重新打开，项目、文献、计划、记录仍在**。
2. 结构化解析论文（研究问题、方法步骤、假设、局限），区分原文证据与模型解释，
   尽量给出可核验的 DOI/URL/页码。
3. 检索相关/后续/相似研究，生成简短的研究发展线与方法对照表；只呈现查证到的文献。
4. 输出学习路线；让用户在**原文复现 / 后续方法对照 / 自主研究设想**三种模式中选择，
   明确目标与成功判据。
5. 接入已通过验证的地震数据处理流程，执行小规模真实数据（质控 → 预处理 → 互相关 → 叠加），
   产出结果图与执行日志。**明确标注所用引擎。**
6. 每次实验保存输入数据标识、配置快照、软件版本、命令、状态、错误与结果文件；
   支持两个实验版本对比。
7. 工作流/流程状态图与可编辑科研备忘录；研究想法分类为「想法 / 待验证 / 已验证」。
8. 目标验收页面：逐条对照起始目标与实际完成情况，导出 Markdown / HTML 复现报告。

### 2.2 P1 —— 有余力实现

- 指定章节翻译与中英对照，显示原文段落与页码。
- PDF / DOCX 报告、可编辑 PPT 导出。
- 多种叠加方法与参数对照实验。
- AI 错误诊断与建议修复（需用户确认后重试）。

### 2.3 P2 —— 明确排除

- 任意学科、任意论文的一键自动复现。
- 一键完成环境噪声成像、频散反演或 Bensen 2007 的全部流程。
- 无审查执行任意代码、海量分布式计算、TB 级云端数据。
- 自动认定"创新"、自动编造实验、自动生成可投稿论文。
- 用多个空壳 Agent 代替真实任务执行。

## 3. 四个工作台

### 3.1 文献探索 Literature Explorer

输入：1–3 篇 PDF；可选关键词、研究目标、目标语言。

1. 上传解析 PDF，形成元信息卡、方法要点、局限。
2. 依据 DOI/标题/关键词检索引用、被引、相似研究，输出带 DOI/URL 的候选清单。
3. 方法发展以时间线 + 对照表展示，区分「年代先后 / 引用关系 / 明确技术改进」，
   **不因年代新就判定更优**。
4. 可选阅读解释、学习路线、指定章节翻译。
5. 选定方法或提出研究问题后进入规划。

输出：`literature_summary.md`、`paper_candidates.json`、`method_comparison.json`、`learning_plan.md`。

### 3.2 复现规划 Research Planner

三类入口：

- A 原文复现：明确要复现哪一步，尽量忠实论文设定。
- B 文献改进对比：列出基线方法、候选后续方法、差异与引用，做控制变量实验。
- C 自主研究设想：用户输入方法与指标，先形成**可检验假设**。

必须明确：目标描述、可用数据、目标步骤、主要评价指标、成功标准。可自动预填，用户确认后生效。

输出：版本化 `reproduction_plan.json`（`goal_id`、`method_id`、依赖、数据条件、步骤、风险、验收指标）。

### 3.3 实验工作台 Experiment Lab

首个真实流程：小规模真实数据 → 质控 → 预处理 → 互相关 → 叠加 → 结果图与日志。

界面：流程节点状态（未开始/运行中/成功/失败/跳过）、运行日志、参数版本、CCF 与叠加图、
指标表、备忘录、待验证假设卡片。

每次实验至少记录：实验 ID、项目 ID、执行时间、状态与步骤；输入数据路径或数据集 ID、
台站/通道/时段、数据哈希（可行时）；软件版本、命令、完整配置快照；输出文件、图像、指标、
异常与备注；对照组 ID 与方法依据。

原则：AI 可建议参数，运行前用户可审阅。日志为真实程序输出，失败显示真实原因，不伪造成功。

### 3.4 科研成果 Research Outcomes

输入：项目初始目标 + 方法 + 实验记录 + 图表。

目标对照：每条目标给出「完成 / 部分完成 / 未完成 / 失败」，附证据链接、未完成原因、下一步建议。

导出：Markdown / HTML 复现报告，含题目、原始目标、论文来源、选定方案、实验流程、参数与版本、
真实结果、方法对照、错误记录、局限与参考资料。PPT / DOCX 属 P1。

## 4. 黄金路径（演示剧本）

1. 新建项目「地震环境噪声互相关研究」。
2. 上传 Bensen (2007) 与 1 篇后续论文，得到有来源的研究脉络、方法对照与学习计划。
3. 选择「原文复现」或「文献改进对比」，明确本次只验证互相关/叠加相关步骤，并设定检查指标。
4. 选择真实小规模数据，运行实验；展示运行日志、进度与 CCF/叠加输出。
5. 改动一项可比较的参数，生成第二次实验；对照报告记录控制条件与实际差异。
6. 写下一个新观察，保存为待验证假设。
7. 打开目标对照，确认完成情况，导出报告。

**演示诚信约束**：耗时长的历史结果可以展示，但必须标注「预先运行」，给出数据范围、代码、
配置与实验时间；现场运行一份小数据，不把预生成图片冒充实时计算。

## 5. 系统架构与技术选型

### 5.1 技术栈

```
Streamlit 界面
  → ResearchPilot Agent（一个主 Agent，理解任务、调用工具、协调流程）
  → 文献层 literature/       PDF 解析 · OpenAlex · Crossref · LLM · 翻译
  → 规划层 planning/         三种复现模式 · 学习路线 · 目标与指标
  → 计算层 engine/           QC · 预处理 · 互相关 · 叠加（自研流程 + NoisePy 适配器）
  → 记录层 storage/          SQLite · 项目 JSON · 实验日志
  → 导出层 exports/          报告 · PPT · 代码包
```

要点：

- **不强制多 Agent。** 第一版一个主 Agent + 一组专业工具。工作流用 Python 实现，
  便于调试与长期维护；`skills/` 只保留方法规范。
- LLM 可替换：API Key 走环境变量，无 Key 时降级为不可用但已存内容仍可查看。
- 界面与业务分离：`src/researchpilot/ui/` 只做调用与展示，不放业务逻辑。

### 5.2 外部服务

| 服务 | 用途 | 约束 |
|---|---|---|
| OpenAlex | 候选文献、引用关系 | 接口失败时明确提示，不编造 |
| Crossref | DOI 与书目核验 | 同上 |
| PyMuPDF | PDF 解析 | 公式、跨栏、扫描件标注「可能解析不完整」 |
| LLM API | 结构化总结、方案生成 | 无 Key 优雅降级；不在代码中硬编码密钥 |

### 5.3 数据与算力

- 原始数据 `/home/wannnlee/seismic/sac_data`（约 40 GB / 4551 个 SAC）**只读引用**，
  通过 `configs/default.yaml` 的 `raw_sac_dir` 为唯一入口，不复制、不移动、不做目录软链接。
- 演示用小规模样例：单台单日或 BJT–SSE 单日，放 `demo_data/`，控制体积。
- 计算在本地 Linux/WSL 完成，不上传原始数据。

## 7. 数据对象

| 对象 | 主键/重要字段 | 说明 |
|---|---|---|
| Project | `id, title, domain, created_at, status` | 一个项目贯穿四工作台 |
| Paper | `id, project_id, title, doi, year, local_path, sha256` | 用户上传或检索到的论文 |
| PaperClaim | `id, paper_id, claim, locator, certainty` | 方法与结论关联到页码/出处 |
| Method | `id, project_id, name, source_paper_ids, limitations` | 原文、改进、自拟方案 |
| Goal | `id, project_id, statement, metric, acceptance, initial_status` | 起始科研目标 |
| PlanVersion | `id, project_id, mode, steps, goal_ids, version` | 计划不可覆盖旧版 |
| ExperimentRun | `id, project_id, plan_version_id, engine, config_path, dataset_id, status, started_at, ended_at, log_path` | 每次运行留存 |
| LabNote | `id, project_id, run_id, kind, text, timestamp` | 备忘、错误、修改、观察 |
| Hypothesis | `id, project_id, text, status, evidence_run_ids` | 想法 / 待验证 / 已验证 |
| Artifact | `id, project_id, run_id, type, path, sha256` | 结果文件、图、报告 |
| GoalAssessment | `id, goal_id, status, evidence_ids, reason` | 目标与实际结果逐条对照 |

实现方式：SQLite 元数据 + 每个项目独立工作目录与 JSON 快照。项目可整体导出归档供评委复现。
所有展示的实验指标都必须能指向具体 `ExperimentRun`。

## 8. 核心业务规则

1. **引用可信**：显示源 DOI/URL/页码；网络不可用时不得补造参考文献，允许标注「暂无外部检索结果」。
2. **方法评价有边界**：新论文不一定优于旧论文；「改进」必须交代条件与证据。
3. **实验真实**：数值来自实际程序输出；指标明确单位、定义、参数与适用范围。
4. **可重复性**：保存配置快照、软件版本、命令、数据标识与时间；尽可能保存哈希。
5. **科研谦逊**：假设与结论分离；未完成、失败、无法复现同样保存。
6. **执行安全**：只执行预定义命令与参数；限制上传大小、运行时长与存储；隔离运行目录；
   不直接运行论文中的任意代码或用户提供的 shell 命令。
7. **隐私与版权**：论文、数据与 API Key 不公开；引用遵循许可与合理使用；不整篇复制传播。
8. **恢复能力**：关闭后重新打开，项目、计划、结果与日志必须保留。

## 9. 功能验收标准

| 编号 | 操作 | 通过条件 |
|---|---|---|
| AT-01 | 新建项目 → 关闭 → 重新打开 | 项目信息与目标仍在 |
| AT-02 | 上传两篇合法 PDF | 正确关联项目，能展示元信息与结构化分析 |
| AT-03 | 检索相关论文 | 至少得到可访问的 DOI/来源；失败明确提示，不编造 |
| AT-04 | 选择原文/改进/自主模式 | 生成可编辑计划与目标/验收标准，确认后保存版本 |
| AT-05 | 运行小数据计算例程 | 生成真实 CCF/叠加结果与命令日志，并标明所用引擎 |
| AT-06 | 模拟一次失败 | 出现失败状态、错误信息、时间与重试记录，不显示假成功 |
| AT-07 | 完成两次可比实验 | 可见两个配置快照、结果图与有约束的差异说明 |
| AT-08 | 保存假设与备注 | 重新打开后仍能找到，标记为待验证 |
| AT-09 | 打开目标对照 → 导出报告 | 每条目标有状态，报告中的结果可追溯到真实 Run |
| AT-10 | 禁用网络 / 无 LLM Key | 已保存项目与报告仍可查看；新 AI 任务有明确错误提示 |

**总验收关口**：至少通过 AT-01、AT-02、AT-04、AT-05、AT-06、AT-08、AT-09。
未通过的功能不得写成已实现。

## 10. 比赛交付

主交付为**可运行代码包**，辅以演示视频；在线链接为可选加项。

| 交付物 | 内容 |
|---|---|
| 作品本体 | 源代码、`requirements.txt`、配置模板、小型演示数据、运行说明 |
| 设计文档 | ≤3000 字，覆盖科研痛点、创新设计、技术方案、实际效果、安全合规 |
| 演示视频 | 3–5 分钟，展示从文献上传到复现报告的真实流程 |
| 承诺书 | 以官方模板与提交要求为准 |
| 选交佐证 | 真实实验结果、测试记录、方法对比、运行截图 |

约定：**2026-10-14 完成上传准备，10-15 只做最终核对与提交。**
