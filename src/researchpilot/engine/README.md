# engine —— 科研计算后端

以 NoisePy 为主要计算后端，允许接入 ObsPy 和已有 Python 算法。
方法不局限于 Bensen 2007，也不限定于海洋微震。

| 目录 | 职责 |
|---|---|
| `readers/` | 读取 SAC / miniSEED / StationXML，统一成内部数据模型 |
| `qc/` | 数据完整率、缺道、采样率一致性检查（不通过则跳过并记日志） |
| `preprocess/` | 去均值、去趋势、加窗、去仪器响应、重采样、带通、时域归一化、谱白化 |
| `crosscorr/` | 互相关（线性互相关，注意区分循环相关） |
| `stack/` | 线性叠加、均值叠加、分时段/分季节叠加 |

硬约束：

1. 本目录不依赖女娲专有 API，保证可迁回独立应用。
2. 只读原始数据，产物一律写入 `outputs/`。
3. 每次运行必须留下配置快照与运行日志。

## 与 `adapters/` 的分工

PRD 第 5.3 节列出的 `NoisePy Adapter` 是**受控执行层**（校验输入、映射参数、
在隔离环境执行白名单命令、解析输出）。本目录 `engine/` 是它下面的**计算核**，
只做纯粹的数据处理，不含命令拼装与子进程调用。

拆成两层的原因：

1. 计算核要能被单元测试直接调用，不经过子进程；
2. 计算核是软著材料里"自主研发模块"的主体，必须与第三方适配层分开；
3. 换后端（NoisePy / 自研 Bensen 流程 / ObsPy）时只换 adapter，计算核不动。
